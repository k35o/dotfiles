# Skill Creator

作成と改善の手順、評価（スキルあり/なしの比較、descriptionのトリガー精度の調整）は、公式プラグインの`skill-creator:skill-creator`を起動してそれに従う。ここにはk8o固有の方針だけを書く。公式と食い違ったらこちらを優先する。

## 何を書くか

- 各指示に「これがなければClaudeは間違えるか」を問い、間違えないなら書かない。書くのはClaudeが持っていない手順、k8oの意見、落とし穴だけにする。
- 落とし穴はSKILL.mdのGotcha節にまとめる。使っていてClaudeを訂正したら、その内容をGotchaに足す。
- 手段が複数あるときは既定を1つ決め、例外だけ添える。選択肢を対等に並べない。
- 長い散文の仕様より、実コード、テスト、実例への参照の方が忠実に伝わる。
- 毎回必ず守らせたいことはスキルではなくhookにする。スキルの指示は会話の途中で守られなくなることがある。
- README.mdやCHANGELOG.mdなどの補助ドキュメントは含めない。スキルにはエージェントが仕事をするための情報だけを置く。

## 言語とdescription

- descriptionと本文は日本語で書く。
- descriptionは「〜するときに使う」と使う場面を先に書き、実際に使う日本語の言い回し（「〜して」「〜したい」）を入れる。分野名を口にしない依頼も拾えるよう、少し押し気味に書く。
- descriptionは数文までにする。スキルの一覧では長い説明が切られ、スキルが多いと説明ごと落ちる。

## 構成

- SKILL.mdは500行かつ5,000トークン以内に収める。コンパクション後に残るのは先頭5,000トークンだけなので、重要な指示ほど上に置く。
- 詳細は`references/`に出し、SKILL.mdから直接リンクする（参照先からさらに参照しない）。リンクには「〜のときに読む」と読む条件を添える。
- 毎回同じ処理をClaudeに書かせているなら`scripts/`に出し、`${CLAUDE_SKILL_DIR}/scripts/...`で呼ぶ。
- リポジトリ作成や公開など副作用のある手順のスキルは`disable-model-invocation: true`にし、明示的に呼んだときだけ動かす。

## 見直す

- 書いたら新しいセッションでスキルあり/なしを比べる。同じセッションでは、それまでの会話が抜けを補ってしまい気づけない。
- モデルの世代が上がったら、自力でできるようになった指示を削る。

## Gotcha

- 個人スキルの正本はdotfilesリポジトリの`dot_agents/skills/<スキル名>/`。chezmoiが`~/.agents/skills`に展開し、`~/.claude/skills`はそこへのシンボリックリンク。展開先を直接編集すると次の`chezmoi apply`で消える。
- 公式skill-creatorはClaude Codeに同梱されていない。`skill-creator:skill-creator`が一覧に無ければ`/plugin install skill-creator@claude-plugins-official`で入れる。
