# work-recap

作業のふりかえりを1枚のHTMLレポートにするスキル。読み手は「作業を隣で見ていなかったユーザー」で、目的はレビューと意思決定。作業ログではなく、最終状態とその根拠を伝える。

長文テキストが中心で足りるなら [mdscroll](../mdscroll/SKILL.md) で十分。before/afterの並置やスクリーンショットなど、視覚的な比較に価値があるときにこのスキルを使う。

## いつ・どう始めるか

- まとまった作業の完了報告をするタイミングで「成果をHTMLで可視化しますか？」と確認する。AskUserQuestionが使えるなら選択肢（作る / 不要）で聞く。
- 小さな修正・単発の質問回答・そもそも成果物がドキュメントの作業では聞かない。確認自体がノイズになる。
- 同じセッションで一度「不要」と言われたら、以後は聞かずに完了報告だけする。
- ユーザーが明示的に依頼したときは確認を挟まず作る。

## 書くこと・書かないこと

レポートの柱は次の4つ。これがユーザーがレビューに必要とする全てで、これ以外のセクションは足さない:

1. **TL;DR** — 何をしたかを2〜4文の地の文で。背景から書き起こす。
2. **変更点（diff中心）** — 変更1件につき、説明段落（2〜4文）→ なぜ → diffハンク＋ハンクごとの説明、の順で書く。diffはテンプレートの `.line add/del/ctx` 構造で本質的なハンクだけを示し、各ハンクの直後に `hunk-note` でそのまとまりが何をしているかを添える。全量diffを貼らない（diffを見たいならユーザーは `cmux diff` やGitHubで見られる）。
3. **要判断・確認したいこと** — 実装中に選択肢が分かれた点、ユーザーの判断が必要な点。何が論点かを説明してから、検討した選択肢・暫定でどちらを選んだか・何を確認してほしいかを結論志向で書く。
4. **UI変更** — 画面のどこがどう変わったか。可能な限りbefore/afterのスクリーンショットを並べる。

レポートは読み物として書く。見出しと断片の箇条書きだけで済ませず、各セクションに地の文の説明を入れる。読み手は作業を見ていないので、diffやスクリーンショットは説明の証拠であって説明の代わりではない。

書かないもの: 途中の試行錯誤・失敗・行き詰まりの経緯。悩んだことに価値があるのは判断材料になるときだけで、それは「要判断」に選択肢として書く。時系列の物語にしない。

## 作り方

1. [assets/template.html](assets/template.html) をコピーして中身を差し替える。デザイン（トークン・角丸・余白）はユーザーの選好で調整済みの完成品として扱い、再スタイルしない。テンプレートにないレイアウトが必要になったときだけ k8o-design スキルを起動して判断する。
2. テンプレートには行コメント機能が入っている: diffの各行に `data-file` / `data-line` を付けておくと、ユーザーが行をクリックしてコメントを書き、右下のトレイから全コメントをコピーしてエージェントに貼り戻せる。末尾の `<script>` は編集も削除もしない。
3. 保存先はセッションのscratchpad配下に `recap/` ディレクトリを作り、HTMLとスクリーンショットをまとめて置く。リポジトリを汚さないため。ユーザーが「残したい」と言ったらプロジェクト内の適切な場所へ移す。
4. HTMLは自己完結にする: CSSはインライン、外部CDN・Webフォントに依存しない（file://で開くのでオフラインでも崩れないこと）。画像は同ディレクトリからの相対パスで参照する。1ファイルで共有したいと言われたらdata URIに切り替える。

## UIスクリーンショット

- **after**: 現在の状態を撮る。agent-browserスキル（`agent-browser open` → `screenshot`）か、cmux内ならcmuxブラウザ（`cmux browser <surface> screenshot --out <path>`）を使う。
- **before**: 変更前リビジョンを安全に再現できるとき（`git stash` で退避できる・別worktreeで旧リビジョンを起動できる）だけ撮る。作業ツリーを壊すリスクを冒してまで撮らない。撮れないときはafter画像に「ここが変わった」注記を添え、変更前の状態は文章で説明する。
- before/afterは同じviewportサイズ・同じページ位置で撮る。条件が揃っていない比較は誤解を生むだけで価値がない。

## プレビュー

- cmux内（`CMUX_*` 環境変数あり）: cmuxスキルに従い、補助ペインのブラウザで `file://<絶対パス>` を開く（`--focus false` を忘れない）。
- それ以外: `open <パス>` でユーザーの既定ブラウザで開く。
- ライブリロードはないので、フィードバックを受けて直したら再読み込み（cmuxなら `reload`、それ以外は再度 `open`）で反映する。
- コメントの回収: レポートを開いているブラウザにエージェントから到達できる場合（cmuxブラウザなら `cmux browser <surface> eval`）、ユーザーに「コメント書いた」と言われたら `document.querySelectorAll(".line[data-comment]")` を評価して直接読み取る。到達できない通常ブラウザで開いている場合は、右下トレイの「コメントをコピー」で貼り付けてもらう。
