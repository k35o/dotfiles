# k8o Design

k8oが好むデザインの方針。基準は言葉より実装 — [references/exemplar.html](references/exemplar.html) が taste を体現した基準実装。迷ったらこのファイルを開き、質感・トークン・密度をこれに合わせる。

## 美学

**触れるものは柔らかく、読むものは端正に。**

LinearやCal.comのような方向性。色ではなく、余白のゆとりと形の柔らかさが個性を作る。レイアウトとタイポグラフィで魅せ、装飾に頼らない。ただし「ただ情報を載せただけ」に見えるのはNG — 意図とこだわりが感じられること。

## 基準トークン

exemplarの要点。プロトタイプ比較で選好確認済み（暖色背景・ボーダー分離・明朝見出し・藍アクセントは不採用と確認）。

| 軸         | 値                                                                            |
| ---------- | ----------------------------------------------------------------------------- |
| ページ背景 | クールな薄グレー `#f3f4f6`。白カードが影で浮く構造                            |
| カード     | 白、`border-radius: 20px`、影 `0 10px 30px rgb(25 35 45 / .06)`、ボーダーなし |
| アクセント | Teal `#0d9488`。配分は60-30-10（ニュートラル/サポート/アクセント）            |
| ボタン     | ピル型。入力欄は角丸14px                                                      |
| フォント   | Noto Sans JP / M PLUS 2。ウェイト3種まで（400/450/700）                       |
| 余白       | たっぷり。`gap-6` 標準、セクション区切りは `gap-8`〜`gap-10`                  |
| モーション | 150〜200ms `ease-out` の静かな変化のみ                                        |

## 要素の性格で使い分け

すべてを同じトーンにしない。

| 要素                                | 方向性                               |
| ----------------------------------- | ------------------------------------ |
| フォーム（input, textarea, button） | 柔らかい（大きな角丸、ピル型ボタン） |
| カード・コンテナ                    | 柔らかい（大きめ角丸、ふんわり影）   |
| 情報表示（Alert, Badge）            | 過度に丸めない。明確さ優先           |
| ナビゲーション（Tabs, Breadcrumb）  | シャープに、端正に                   |

## 避けるもの

- 揃っていない整列: フォーム行に並ぶ入力・セレクト・ボタンは同一高さにして端を揃える（exemplarの `--control-h` 参照）。`align-self` や目分量のpaddingで高さの違うコントロールを近づけただけの配置にしない
- 過度なボーダー: 分離は余白と影で行う。カードの輪郭線、リスト行ごとの区切り線、セクションを囲う枠線を安易に引かない。ボーダーは入力欄や表など明確さが必要な箇所だけ
- 背景とカードが見分けられない配色: ページ背景は白カードとはっきり区別できる薄グレー（exemplarの `#f3f4f6`）にする。`#fafafa` のようなほぼ白の背景に白カードを置かない（浮かないうえ、補償でボーダーを引きたくなる）
- AI感の出るもの: 紫・ネオンのグラデーション、テキストグラデーション、bounce/spring、装飾絵文字の多用、Inter/Roboto等の汎用フォント
- カードの入れ子
- 透明度によるステート表現（`/90`, `/80`）
- 日本語テキストへの `uppercase` や `letter-spacing` 拡大
- 情報を並べただけの素っ気ないレイアウト

## ライト/ダーク

ライトモードが本命。ダークは色の単純な反転ではなく、独立したトーン設計にする。

## ArteOdyssey

使えるプロジェクトではそのコンポーネントとセマンティックトークンに従う（使い方はArteOdyssey側のドキュメント参照）。ない場合は基準トークンをセマンティックなカスタムプロパティとして定義してから使い、生のTailwindカラー（`bg-teal-500`）を直書きしない。
